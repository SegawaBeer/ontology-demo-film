## 一、要写的脚本

### 1. `scripts/final/export_segment.py URL OUT.mkv START END [--scale 2]`

- 逐帧导出页面的一段：第 n 帧是 t = START + n/60，一共 round((END − START) × 60) 帧。
- 做法照 `scripts/export-clip.py`（在 film-main 里，只读参考，复制过来改）：
  - 地址自动补 `&play=0`。
  - 等 `document.documentElement.dataset.ready === '1'` 和 `document.fonts.ready`。
  - 开录前检查画面是否静止：隔两帧截图，像素必须相同。不同就报错退出。
  - 每帧 `window.__seek(t)` 后截图，用管道送进 ffmpeg。
- 输出：无损 H.264（`-qp 0`，`yuv444p`），mkv 容器，60 帧每秒。scale 2 时是 3840×2160。
- 每 300 帧打印一次进度和预计剩余时间。
- 中途失败可以续跑：加 `--from-frame N`，把新导的部分写成另一个文件，最后合并。

### 2. `scripts/final/assemble.py`

参数：

```
assemble.py --seg opening.mkv:0:30 --seg film.mkv:30:103 --seg ending.mkv:103:120
            --audio 音频/全片音效.wav --out 成片/本体能力演示
```

做这几件事：

1. 检查：各段首尾相接，没有缺口和重叠；帧数等于时长 × 60。
2. 拼接：用无损方式拼成一条（concat 分离器 `-c copy`；拼不上就解码后重新无损编码）。
3. 拼接点比对：
   - 每个拼接点前后各两帧，从拼好的文件里解出来，和原段对应的帧逐像素比，必须完全相同。
   - 拼接点两侧相邻两帧的平均通道差也写出来。这个数只报告，不判过不过。
4. 出两个成品：
   - `成片/本体能力演示-4K60.mp4`：H.264 high，crf 14，preset slow，yuv420p，3840×2160，60 帧每秒，`+faststart`。
   - `成片/本体能力演示-1080p.mp4`：从同一条无损中间文件缩放（lanczos），crf 16。
   - 两个都合上音轨：AAC 320k，48 kHz，立体声，从 0 开始。
5. 用 ffprobe 核对两个成品：
   - 时长 120.000 秒，视频帧数 7,200。
   - 音频 120.000 秒，差 ≤ 1 帧。
   - 分辨率、帧率正确。
6. 抽帧拼版：1080p 成品每 0.5 秒抽一帧（240 张），缩成 12 列的拼版，存 `成片/拼版-每0.5秒.jpg`（不要 PNG，控制在 20 MB 以内）。另存一张每 3 秒一帧（40 张）的拼版 `成片/拼版-每3秒.jpg`，给人快速过目。
7. 写 `成片/成片记录.json`：每一步的结果、拼接点数据、ffprobe 结果。
8. 删掉中间文件。

### 3. `scripts/final/check_final.py 成片/本体能力演示-4K60.mp4 --seg URL:START:END ...`

- 每段每 2 秒抽一帧，和页面在同一时刻的直接截图比（截图用 scale 2，3840×2160），平均通道差 ≤ 2.0。
- 对音轨：
  - 用 ebur128 量整体响度和真峰值，写出来。
  - 真峰值必须 ≤ −1 dBTP。
  - 开头 0.3 秒和最后 0.5 秒都是静音。
