# 任务：把涡扇发动机模型重新拆分成可单独控制的零件

## 背景

这个项目是一支约 2 分钟演示视频的三维部分。视频最终会做成按时间轴自动播放的本地网页：左边是对话框，中间是这台发动机，右边是“本体”关系图。三维模型要配合脚本完成这些动作：从空白开始，一个零件一个零件地组装出整机；一圈叶片里的任意几枚单独变色、单独抽出来；某个模块单独变暗或变半透明；整机爆炸展开；再复制出第二台发动机。

现在的模型只拆到 9 个大段，只能整段选中、整段变色，做不到上面这些动作。你的任务是重新拆分模型，并给运行代码提供按零件控制的接口。对话框、关系图、时间轴和视觉样式都不在这次的范围内。

## 项目现状

- 项目目录：<项目目录>。这是一个 git 仓库，主分支是 main。技术栈是 Three.js + TypeScript + Vite，纯前端。
- 原始模型：~/Downloads/turbine__turbofan_engine__jet_engine.glb，来自 Sketchfab，作者 blenderbirb，许可证 CC BY 4.0。共 235,778 个三角形，6 种材质：accent-yellow、metal-bright、metal-dark、metal-mid、plastic-cone-black、plastic-grey。网格按材质合并，没有零件层级。这个文件只读，不要修改。
- 转换脚本：tools/glb_pieces.py 把每个网格拆成连通块，一共 3,542 块。tools/convert_turbofan.py 按轴向位置和半径把连通块归到 9 段，每段再分 rotor、static、shell 三层，写出 public/models/turbofan.glb。在项目根目录运行：python3 tools/convert_turbofan.py ~/Downloads/turbine__turbofan_engine__jet_engine.glb public/models/turbofan.glb
- 坐标：x 轴是发动机轴线，风扇在 +x 一端（约 1.3 到 2.2），尾部在 −x 一端（约 −1.9）。半径 r = hypot(y, z)。
- 运行代码：
  - src/model.ts 加载模型，定义 9 段的中英文名。
  - src/main.ts 负责装配、剖面、爆炸三种视图，以及点选、单独显示和运转。
  - src/effects.ts 按 combustor 和 exhaust 两段的位置放置燃烧光效和尾焰。
  - scripts/verify-model.mjs 对应 npm test，目前检查 9 段、三角形总数和 fan-rotor 节点。
- 运行方式：npm run dev。.claude/launch.json 里有 turbofan-dev 配置；5173 端口被占用时会自动换端口，以实际输出为准。测试用 npm test，构建用 npm run build。

## 初步观察（需要你核实）

1. 风扇有 16 片叶片，每片是一个独立连通块（metal-mid，432 个三角形）。每片叶尖另有一块黄色小件（accent-yellow，96 个三角形），也是 16 块。
2. 现在叫 exhaust（尾喷管）的那一段，里面其实是 5 级涡轮叶片，轴向位置约为 x = −1.36、−1.45、−1.54、−1.64、−1.75。每一级有 100 块靠内的薄片（r 约 0.30 到 0.45）和 75 块靠外的薄片（r 约 0.46 到 0.64）。每块只有 2 个三角形，是一块平板。
3. 现在叫 turbine（涡轮）的那一段（x 约 −1.00 到 −0.12）看起来是一个鼓筒，外面排着方块和螺栓，没有叶片。
4. 压气机区有若干圈重复件：x≈1.05 一圈 128 块；x≈0.86、0.70、0.58 各一圈 50 块；x≈1.00 到 1.11 有 7 个独立圆环，半径逐个减小。另外在 x≈0.70 有 8 根径向支板，r 从 0.35 到 0.74。
5. 螺栓有两圈，每圈 64 个：一圈在 x≈0.13 到 0.21、r≈0.52 到 0.55，另一圈在 x≈−1.87 到 −1.92、r≈0.70 到 0.73。每个螺栓由几个小连通块组成。
6. plastic-cone-black 这个材质可能是风扇前面的整流锥。

这些都是从几何统计推出来的。零件到底是什么，以渲染出来的样子为准。

## 要做的事

### 1. 四层零件层级

整机 → 模块 → 组件 → 零件。

- 整机：一台发动机。
- 模块：固定 9 个。id 和中文名如下，后面的视频脚本要按这 9 个核对：
  - fan 风扇：16 片风扇叶片、轮毂、整流锥
  - fan-cowl 进气罩
  - compressor 压气机：每一圈叶片一个组件，从前往后编号为“压气机第 N 级”
  - combustor 燃烧室
  - turbine 涡轮：5 级涡轮叶片（目前放在 exhaust 段里，要移过来），每级一个组件，名为“第 N 级涡轮叶环”。如果每级有单独的轮盘几何，轮盘也单独成组件，名为“第 N 级涡轮盘”。
  - exhaust 尾喷管：尾锥、喷口
  - core-casing 核心机机匣
  - nacelle 外涵道机匣
  - shaft 主轴
- 组件：每一圈叶片、每个轮盘、每一圈螺栓、每段机匣，都是一个组件。
- 零件：单片叶片、单个螺栓这一层。一个零件可能由几个连通块组成，比如一个螺栓由几个小块组成，一片叶片可能还带着叶尖小件。同一角度位置、包围盒相互重叠的连通块，合并成一个零件。
- 现在叫 turbine 的那个鼓筒（x 约 −1.00 到 −0.12），按渲染出来的样子判断它是什么，归到 turbine 或 core-casing，并在报告里写明理由。
- 认不出的连通块放进所在模块下一个叫“其他”的组件里。每个原始连通块都必须恰好归到一个零件里，不能丢，也不能重复。唯一的例外是下面“2. 第一级涡轮叶环换成有翼型的叶片”里被替换掉的那 100 块平板。
- 中文名用通用叫法，例如“压气机第 3 级叶环”“第一级涡轮叶片”“机匣螺栓”。不要用任何厂商或具体机型的术语。

### 2. 第一级涡轮叶环换成有翼型的叶片

- 第一级是最靠近燃烧室的那一级，x≈−1.36。把这一级靠内的 100 块平板（r 约 0.30 到 0.45）换成 100 枚程序生成的涡轮叶片，等角度排一圈，每一枚都是一个独立零件。
- 叶片形状：有弯度、有厚度的翼型截面，前缘是圆的，从叶根到叶尖带扭转；下面有缘板和简单的叶根（燕尾形或枞树形）。视频开头这枚叶片会单独出现在空白背景上慢慢转，所以单独看时必须一眼就是一枚涡轮叶片，不能看起来像一块板。可以参考 MIT 许可的 AlexZhangji/turbine-explorer 仓库中 src/blade-study.ts 里的 bladePoint 翼型函数；如果借用了代码，要在 THIRD_PARTY_NOTICES.md 里注明来源。
- 材质和周围一致，尺寸要正好落在原来那圈平板的位置，不能和轮盘、机匣穿插。
- 每枚叶片的局部坐标原点放在叶根中心，局部 Y 轴沿径向朝外。这样单独旋转一枚叶片、或者把它沿径向抽出来都很直接。
- 同一级靠外的 75 块（r 约 0.46 到 0.64）先弄清楚是什么，作为单独的组件保留，不要替换。如果它们看起来和内圈是同一片叶片的上下两半，换掉内圈后会显得不协调，就停下来写进报告，不要自己改数量。
- 第二到第五级保留原来的几何，只按片拆开。如果把同样的翼型套用到这几级很简单，可以一起做，并在报告里说明。

### 3. 零件编号和数据清单

- id 规则：模块用 turbine；组件用 turbine.stage-1-blades；零件用 turbine.stage-1-blades.001。Three.js 节点名直接用这些 id。
- 一圈里零件的编号：按 θ = atan2(z, y) 换算到 0 到 360 度，从 θ 最小的那个开始编 001，按 θ 递增。所有成圈的零件都按这个规则编号。
- 生成一个数据清单 public/models/turbofan-parts.json，包含：
  - 每个模块和组件：id、中文名、所属上级、零件数量、在组装顺序里的序号（见第 6 条）
  - 每个零件：id、中文名、类型（叶片、螺栓、轮盘、机匣等）、所属组件、序号、中心点、轴向范围、半径范围、是否随转子转动
- 视频右侧的关系图会直接读这个清单，所以清单里的数量必须和模型里实际的零件一一对应。

### 4. 运行时接口

在 src/model.ts 里提供按 id 操作的接口，参数可以是零件、组件或模块的 id，也可以是 id 列表：

- 设置颜色、清除颜色
- 变暗，变暗的程度可调，脚本里要求暗到原来的两成左右
- 半透明，透明度可调。半透明部件后面的东西要能正确地看到，不能变黑、闪烁或者互相穿插。
- 显示和隐藏
- 相对装配位置的平移和旋转，用来把零件抽出来或者摆到一边。被移开的零件在运转时不能再跟着转子转。
- 全部恢复到初始状态
- 查询：按 id 取对象；列出某个组件下的全部零件；点击模型时返回被点中的零件 id

性能方面：

- 成圈的重复零件建议用 InstancedMesh，或者按组件合并成一个网格并给每个顶点记录零件序号。不要做成几千个独立网格，否则绘制调用会太多。具体用哪种方案由你决定。
- 不管底层怎么实现，接口都按零件 id 操作，调用方看不到实例序号之类的细节。
- 改一个零件的颜色，只能影响这一个零件。注意避免材质共享，否则一改全变。

以后还会加两个视觉效果：零件出现时先只显示轮廓线、再铺上材质；高亮时加描边。这两样这次不用做，但数据结构要保证以后能取到单个零件的几何。

### 5. 第二台发动机

提供一个函数，复制出一台独立的发动机。几何可以共享以节省内存，但颜色、透明度、位置、运转等状态必须完全独立：改其中一台，另一台不受影响。视频里第二台缩小后摆在第一台旁边，两台可以同时运转。

### 6. 组装顺序

在数据清单里写一份组件的组装顺序，按视频脚本从里往外装：

1. 第一级涡轮叶片
2. 第一级涡轮盘
3. 第二到第五级涡轮叶环
4. 主轴
5. 压气机各级叶环
6. 燃烧室
7. 核心机机匣
8. 风扇叶片和轮毂
9. 外涵道机匣和进气罩
10. 尾喷管和整流锥

组装动画不在这次范围内。这次只需要提供一个调试状态：只显示顺序里前 N 步的组件，用来检查顺序和每一步看起来是否完整。

### 7. 现有功能保持可用

- 装配、剖面、爆炸三种视图，点选，单独显示，运转和声音，都要照常工作。
- 左侧部件列表改用 9 个模块的新名字。
- src/effects.ts 现在按 combustor 和 exhaust 两段的位置放置燃烧光效和尾焰。模块的内容变了以后，光效和尾焰要仍然出现在燃烧室和尾部的位置上。
- 爆炸视图里每个模块的展开方向，按新的模块内容重新调整，不能互相穿插。

### 8. 调试状态

用网址参数切换下面这些状态，每个状态截一张图，存到 review/model-split/ 下（这个目录已在 .gitignore 里）：

- 装配、剖面、爆炸三种视图各一张，对照修改前，检查有没有零件缺失或闪烁
- 只显示一枚第一级涡轮叶片，放在画面中央，空白背景
- 第一级涡轮叶环里连续 16 枚变红，其余保持原样
- 这 16 枚从叶环里抽出来，摆在发动机旁边，叶环上留出空位
- 除第一级涡轮叶环以外全部变暗
- 燃烧室模块半透明
- 两台发动机，第二台缩小放在旁边，它的第一级涡轮叶环里有 30 枚变红，第一台不受影响
- 组装顺序的第 1、3、6 步，以及全部装完

测试用的颜色随便选，正式的配色以后再定。

## 约束

- 不修改 ~/Downloads 里的原始模型。转换脚本必须能用一条命令从原始模型重新生成 public/models/turbofan.glb 和 turbofan-parts.json，并把这条命令写进 README.md。
- 转换的输入只有原始模型和你的转换脚本，不手工编辑生成出来的文件。
- 第一级叶片的几何由代码生成，可以放在转换脚本里，也可以在运行时生成，但必须能重复生成同样的结果。
- 不引入新的依赖。如果实在需要，用固定版本号，并在报告里说明原因。
- 生成的 GLB 不超过 15 MB，动态加载耗时不超过 3 秒。
- 在一台普通笔记本上，1920×1080、两台发动机同时运转时，画面保持 60 帧左右。在报告里写明你实测的绘制调用次数和帧率。
- 更新 THIRD_PARTY_NOTICES.md 和 docs/SOURCES.md 里关于模型改动的说明，保留原作者的署名和许可。
- 在新分支 model-split 上工作，按步骤分几次提交，不要推送到远端。项目目录里的“脚本”“任务说明”两个文件夹不要动，也不要提交。
- 遇到下面这些情况，停下来写进报告，不要自己猜着改：
  - 某些零件判断不出是什么
  - 9 个模块的划分和几何对不上
  - 第一级叶片的数量、尺寸放不进原来的位置
